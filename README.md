# SimTest 想定编辑 Demo

根据本项目需求描述、当前 JSON 示例和产品设计文档制作的可交互 Demo。装备型号目录与行动类型目录已接入本地 SQLite 后端，配套文件通过后端校验和生成；一条记录对应一个具体型号，`mxlx` 为唯一主键，前端通过接口读取后按四级分类构建实体。方案和模拟记录暂时保存在浏览器 LocalStorage，所有运行、判读证据和复盘轨迹均明确标识为模拟。

## 启动

在本项目目录运行（Node.js 22.13 或更高版本）：

```bash
npm start
```

打开 [本地 Demo](http://127.0.0.1:4173)。若端口已占用，可用 `PORT=4174 npm start` 更换端口。

启动命令会同时提供静态页面、型号及行动接口并创建 `data/simtest.sqlite`。请使用该服务访问；直接双击 HTML 或只启动静态服务器时无法连接型号数据库。地图数据和样式均已放在项目内，浏览器不需要访问外部地图或 CDN。

查看数据库中的型号：

```bash
npm run db:models
```

## 建议体验顺序

1. 打开“基础行动验证”，查看地图和双方实体。
2. 点击“添加实体”，选择地图实体或挂载实体，再按四级分类选择模型。地图实体可选择是否作为编队；挂载实体需要选择所属主实体和挂载关系。
3. 为蓝方实体添加机库中的飞机；机库存在后，再添加武器库中的武器。也可直接挂载武器。在“模型与行动 → 行动目录”添加行动类型，勾选该类型需要的字段。然后切换方案的“行动指令”，选择类型，填写启用的参数；可多选同阵营、同型号的实体，并为每个实体批量添加 1–50 条行动。
4. 点击“生成文件”，查看严格 JSON；下载配套 ZIP，检查 `scenario/` 和 `command/` 下的同名文件。
5. 点击“模拟运行”，选择待复核、全部成功、事件缺失或运行失败。
6. 在运行详情查看日志、行动证据和产物，保存人工备注，打开演示复盘并拖动时间轴。
7. 回到方案管理勾选多项，体验串行批量、错误项跳过和取消。模型目录支持新增和 JSON 导入，设置可以保存和导出。

刷新后数据仍会保留：装备型号和行动类型来自 SQLite，方案、设置和已结束的运行来自浏览器存储；正在执行的模拟记录会标为已中断。尚未保存的方案修改会在离开时提示。清理浏览器站点数据会删除尚未后端化的记录，不影响 SQLite 中的型号和行动类型目录。

## 已实现

- 方案新建、从固定示例创建、复制、搜索、筛选、归档和恢复。
- 离线地图平移、缩放、定位、实体布置、拖动及坐标表单双向编辑。
- `llbznm` / `zyId` 两种引用分支、33 位字符串实例 ID、模型名称及编码分别保存。
- 实体支持按同一模型一次添加 1–50 个；“添加为编队”未勾选时按普通实体创建，地图单击后自动排布。
- 装备模型保存四级分类、显示名称、型号编号和模型编码；模型目录按分类分组，添加实体时通过四级联动选择器筛选模型。
- 装备型号通过本地 SQLite 单表维护；同一显示名称可对应多个具体型号，新增和批量导入均通过后端接口持久化。
- 机库和武器库是挂载关系，不是模型；机库中添加飞机实体，武器库中添加武器实体，且只有存在机库飞机时才能添加武器库武器。
- 行动从执行者直接挂载或武器库中的武器实体中选择型号，使用量受该型号的累计分配约束。
- 行动类型使用 SQLite 的 `action_types` 表维护，除代码和名称外，21 个字段均为启用标记；启用时显示必填表单，禁用时不输出；开始、结束时间独立于类型配置，所有行动固定必填。
- 支持示例中的全部嵌套参数：执行者与可选编成、目标、武器使用、区域、航路、雷达、补给、干扰及行为策略。
- 同型号实体批量添加同一种行动，每条行动生成独立编号；按执行者和相同策略分组，编辑和复制保留类型快照。
- 结构、ID、引用、阵营、时间、坐标、单条和累计库存校验。
- 想定和指令从同一份状态生成，双文件预览、单文件下载及配套 ZIP。
- 独立 Mock API、串行队列、取消、运行输入快照和模拟异常。
- 逐行动结果、证据展开、模拟事件下载、人工复核历史及演示复盘。
- 模型新增、导入与导出、外部程序及目录配置的本地保存。
- 桌面与小屏响应式布局、键盘焦点、弹窗焦点限制及本地存储失败提示。

## 当前边界

- 文件生成已接入后端，返回两份 JSON 供浏览器预览和下载；尚不向配置目录发布文件，也不启动或控制真实仿真器。
- 装备型号和行动类型目录已实现本地后端；方案、实体、行动、设置和模拟运行记录仍保存在浏览器，尚未迁移到数据库。
- 配置页中的程序和目录值只保存，不验证文件系统存在性，也不实际写入配置目录。
- 行动目录初始提供 000680，可新增六位数字代码的行动类型。字段结构以当前示例为准；自由文本参数的实际引擎枚举语义仍需接入仿真器时确认。
- 挂载实体不单独显示地图标记，也不能作为行动执行者或目标；它的位置和阵营跟随所属主实体。
- 未配置真实行动与事件映射。通过和不通过来自用户所选的模拟情形，默认结果为待复核。
- 演示复盘的位置为初始坐标的示意插值，不是实体态势文件的真实回放。
- 生成接口复用领域校验，检查字段、引用、时间、库存及坐标；真实引擎执行规则和判读映射尚未接入。

## 代码结构与后端接入

```text
frontend/
  index.html           页面入口
  styles.css           布局、组件和响应式样式
  app.js               页面、表单、对话框和交互
  core.js              实体/行动模型、引用、校验、JSON 生成和 ZIP
  api.js               型号与行动接口、后端生成、本地方案缓存及模拟执行
  action-schema.js     行动字段结构、默认值、配置校验与输出
  action-ui.js         行动类型管理、动态嵌套表单与批量添加
  map.js               地图投影、布点、选择及拖动
  assets/land.geojson  内置 Natural Earth 底图数据
backend/model-store.mjs SQLite 型号表、校验、查询和批量写入
backend/action-store.mjs SQLite 行动类型表与字段开关
scripts/serve.mjs      静态页面、目录及生成 HTTP API
scripts/list-models.mjs 数据库型号查看命令
data/simtest.sqlite    启动后生成的本地数据库
tests/                领域及模拟接口回归用例
output/playwright/    浏览器验证脚本、截图和导出样本
```

页面通过 `api` 完成数据读写。`snapshot()` 当前返回缓存快照，异步写入方法完成后发送 `simtest:update` 通知页面更新。接入后端时保留页面消费的对象形状，以 HTTP 请求更新缓存；运行推送或轮询负责更新运行记录。

| 接口 | 现有行为 | 后端接入点 |
| --- | --- | --- |
| savePlan / createPlan / copyPlan | 本地持久化和引用重写 | 方案数据库、服务器分配 ID、版本管理 |
| generate | `/api/generate` 校验并返回两份 JSON | 后续增加原子文件发布 |
| saveActionType | `/api/action-types` 新增和更新类型 | 已接入 SQLite，保留已有行动配置快照 |
| enqueue / cancel | 计时器驱动的串行模拟 | 运行队列、进程或服务适配器、超时与取消 |
| review | 单独追加人工结论和历史 | 复核记录持久化 |
| addModel / importModels | 写入本地 SQLite 型号表 | 已接入；后续增加编辑、停用和版本管理 |
| saveSettings | 浏览器保存配置 | 设置服务、路径及引用校验 |
| 演示复盘 | 浏览器内模拟轨迹 | 独立复盘接口调用外部程序 |

前端不会把原始样例中不一致的 `ybnm`、执行者、目标或武器引用直接拼在一起。生成器根据当前方案重新构建引用；内部说明和模拟标识不会混入两份仿真输入 JSON。

## 验证

```bash
npm test
```

33 项回归检查覆盖双文件一致性、ID 分支、挂载实体聚合、机库与武器库依赖、分类与关系匹配、复制后父子引用、库存累计、无效输入、2×3 指令展开、ZIP 文件完整性、SQLite 持久化、型号主键、接口读写、批量导入原子性、固定示例来源、串行取消及快照隔离；另覆盖行动字段与示例一致性、全部嵌套参数、字段省略、唯一编号、策略分组、类型持久化和后端生成校验。ZIP 检查额外使用 Python 3 标准库。

浏览器验证脚本和截图保存在 `output/playwright/`，验证时使用独立的 Playwright 浏览器会话，不影响日常使用的浏览器数据。

产品范围参考 `产品设计文档_v1.0.md`；型号数据库结构和接口见 `后端第一阶段说明.md`，行动类型及构建流程见 `行动指令构建说明.md`。本 Demo 的具体完成范围及边界以本 README 为准。

# 仿真通用模版总结

> 依据本目录四个样例文件总结：`指令模版.json`、`想定模版.json`、`事件态势模版.json`、`实体态势模版.json`。
> 本文档已做脱敏处理：具体装备型号、具体地名、内部编号均替换为占位符（如 `某机型`、`某区域`、`<编号>`），仅保留系统字段名。
> 标注说明：【事实】= 从样例中直接读出；【推测】= 根据命名/取值的合理推断，以系统定义为准。

---

## 1. 总览

| 文件 | 文件格式 | 数据性质 | 一句话定位 |
|---|---|---|---|
| 想定模版.json | 单个 JSON（带注释） | 静态配置 | 一次仿真的**初始设定**：起止时间、地理/气象环境、双方兵力部署。两种想定风格（带环境完整版 / 无环境精简版，`想定模版.json` 与 `A616.json`）已合并为统一结构，见 §4 |
| 指令模版.json | 单个 JSON（带注释） | 静态配置 | 给实体的**行为规则**：由谁执行、对谁、用什么、何时开始/结束、附带策略开关 |
| 实体态势模版.json | NDJSON（每行一帧，样例 1080 行） | 仿真输出 | 每 10 秒一帧的**实体状态快照**流（位置、航向、油量、毁伤等） |
| 事件态势模版.json | NDJSON（每行一帧，样例 21 行） | 仿真输出 | 离散**事件流**（报告、日志、任务、毁伤、退出等），帧内可含 0~多个事件 |

两者关系【推测】：想定（初始世界）+ 指令（行为规则）→ 仿真引擎运行 → 输出实体态势 + 事件态势两个数据流。

### 1.1 格式注意【事实】

- `想定模版.json`、`指令模版.json` **不是严格标准 JSON**：含 `//` 或 `#` 行内注释、个别尾逗号。解析前需去注释，或按宽松 JSON（JSON5 风格）处理。
- 两个态势文件是 **NDJSON**：每行一个完整独立 JSON 对象，行与行之间靠重复的"帧头"关联。
- 大量字段值是**字符串化的 JSON**（值本身是 JSON 文本，如 `DetectRange: "{\"default\":700000.0}"`），解析时需要二次 `json.loads`。

## 2. 四文件通用约定

### 2.1 字段命名【推测】
- 两种风格混用：拼音缩写键名（想定模版为主：`cjlx` 想定类型、`kjhjList` 计划环境、`qydw` 区域范围、`kssj/jssj` 开始/结束时间、`wb/bzmc` 部队/编队名称）+ 英文键名（态势文件为主：`EntityID`、`timeStamp`）。
- 键名规律：`xxmc`=名称、`xxnm`=ID/编号、`wd`=纬度、`jd`=经度、`gc`=高度、`sl`=数量、`lx`=类型、`mc`=名称、`nm`=编号、`list` 后缀=数组。

### 2.2 时间格式【事实】
- 想定文件：`YYYY-MM-DD HH:MM:SS`（如 `2027-04-01 10:00:00`），另有中文展示格式 `YYYY年MM月DD日 HH时`。
- 态势文件：帧头用 `YYYY/MM/DD HH:MM:SS`；事件内 `timeStamp`/`finishTime` 用**相对秒数字符串**（如 `"30.000000"`，相对仿真开始）。

### 2.3 坐标【事实】
- 经纬度：十进制度数（float 或字符串），高度单位米。
- 想定中区域边界另存"度分秒"字符串：`jd: "120,30,0.00"` / `wd: "25,36,50.66"`（度,分,秒）。

### 2.4 ID 体系【事实】
- 长数字 ID：如 `00000000000001770117389929585392`（38 位补零），用于实体/环境/区域等对象编号，四个文件间靠它互相引用。
- 短业务 ID：如 `1-G5QN0r_ATcRAEt1_50`（兵力编号）、`052CQZJ_1`（指令执行者）、`F-15E_1` 风格（实例 = 类型 + 序号）。
- 类型编码：如 `CMRM0303511000038`（装备/模型类型码）、`CMRE010205301`（事件分类码）。模版中统一写 `<类型码>`。

### 2.5 阵营【事实】
- 双方以 `Blue` / `Red` 表示（事件、实体中出现），模版中记为 `<阵营: Blue|Red>`。

## 3. 模版①：指令模版（rules）

**用途**【推测】：定义一条或多条"某实体在某时间段内对某目标执行某动作"的规则，附行为策略开关。

### 3.1 结构骨架

```
{
  "rules": [                       // 规则数组（样例含 1 条，可多条）
    {
      "fanm": "<规则指纹/名称hash>",        // 32位十六进制串
      "ybnm": "<所属兵力编号>",              // 关联想定中的 ybnm
      "ruledata": [
        {
          "action": [ ... ],        // 动作列表（见 3.2）
          "ruleconfig": [ ... ]     // 行为策略配置（见 3.3）
        }
      ]
    }
  ]
}
```

### 3.2 `action[]` 单条动作字段

| 字段 | 类型 | 说明【推测】 |
|---|---|---|
| `action_id` | string | 动作实例 ID（如 `<执行者ID>_1`） |
| `related_force` | string[] | 兵力配置 |
| `executor` | object[] | 执行者（可多个） |
| `executor[].executor_id` | string | 执行者实例 ID |
| `executor[].formation_struct` | object[] | 执行者编队构成 |
| `executor[].formation_struct[].formation_id` | string | 编队实例 ID（`类型_序号`） |
| `...entity_type` / `entity_name` / `entity_count` | — | 编队内某机型/实体类型码、名称（可空）、数量 |
| `...mount` | object[] | 挂载信息：`mount_type`（挂载类型码）、`mount_type_name`、`num`（数量） |
| `target` | object[] | 目标：`target_id`（目标实例 ID） |
| `launch` | object[] | 发射/使用参数（可空，视动作类型） |
| `launch[].weapon_type` / `weapon_num` | string/int | 武器类型码、数量 |
| `launch[].target_id` / `target_child_id` | string | 武器打击目标、目标子单元 |
| `launch[].way_points` | object[] | 航路点：`{longitude, latitude, height, order}` |
| `region` | object[] | 动作作用区域（action 级）：`points[]`（同航路点结构）+ `region_type`（区域类型码，如 `01`） |
| `route` | object[] | 航线（action 级）：`points[]` |
| `radar_angle` | object | 雷达工作角限：`start/end_horizontal_angle`、`start/end_vertical_angle` |
| `upstream_entity` / `downstream_entity` | string[] | 上游/下游实体分类码（链路关系） |
| `supply` | object | 补给约束：`refuel`（加油比例）、`weapon_type[]`、`weapon_count[]` |
| `start_time` / `end_time` | int | 动作起止（**相对秒**，样例 40 / 5400） |
| `jam` | object | 干扰参数（可选）：`jam_type`（如 radar）、`jam_mode`（如 block） |
| `rule_type_code` | string | 动作规则类型码（6 位数字） |

### 3.3 `ruleconfig[]` 策略开关

```
{
  "is_auto_attack": true,                  // 自动攻击
  "is_auto_return": { "auto_return": true, "airport_id": "<机场ID>" },//是否自动返航
  "is_task_continue": true,                // 任务是否继续
  "is_hidden_maneuver": false,             // 隐蔽机动
  "is_consider_environment": false,        // 是否考虑环境
  "is_auto_deterrence": false,             // 自动威慑
  "is_deterrence_auto_return": false,      // 威慑后自动返回
  "radar_detect_mode": { "detect_mode": "scan", "target_list": ["<实体ID>"] },
  "intercept_strategy": 1.0                // 拦截策略系数
}
```

## 4. 模版②：想定模版（想定/初始设定）

**用途**：一次仿真的静态设定，顶层 6 个键【事实】：

| 顶层键 | 类型 | 说明【推测】 |
|---|---|---|
| `cjlx` | string | 想定类型码（样例：`fajhty` / `TEST`，含义以系统码表为准） |
| `startTime` / `endTime` | string | 仿真起止 `YYYY-MM-DD HH:MM:SS` |
| `kjhjList` | object[] | 环境列表（层级化区域 + 气象数据），**可选**（精简想定可省略） |
| `yb` | object[] | 兵力列表（每方一条，样例 2 条 = 蓝/红双方） |
| `ybnm` | string | 想定（方案）总编号 |

### 4.1 `kjhjList[]` 环境条目

```
{
  "hjnm": "<环境ID>", "hjmc": "<环境名称，如某海域>",
  "kjbm": "<区域编号>", "sjnm": "<上级ID（顶层为-1）>", "xdnm": "<想定ID>",
  "sfgk": null, "xh": null, "zdhb": null, "zxhb": null,
  "zzqy": {                      // 所辖区域
    "kjbm": "<区域编号>", "qylx": "01",         // 区域类型码
    "qymc": "<区域名称>", "sfgk": null, "xdnm": null,
    "qydw": [                     // 区域边界点（多边形）
      { "dwid": "<点ID>", "jd": "<度,分,秒>", "wd": "<度,分,秒>",
        "jd_lon": 120.5, "wd_lat": 25.3, "gc": 0.0, "jdwz": null }
    ]
  },
  "children": [ ... ],            // 子环境，结构同父（可递归）
  "qxdxList": [ ... ]             // 气象/环境数据（见 4.2）
}
```

### 4.2 `qxdxList[]` 气象数据条目（字段较多，大量可为 null/空）

```
{
  "qxnm": "<气象ID>", "hjnm": "<所属环境ID>",
  "kssj": "YYYY年MM月DD日 HH时", "jssj": null,
  "startTime": "YYYY-MM-DD HH:MM:SS", "endTime": null,
  "cx": "", "lg": "", "fx": null, "fxds": null, "tqnm": "", "ylnm": null,

  "jxlList": [null], "jslList": [null], "jxfsList": null, "wxfsList": null,
  "hjxx": {                        // 环境数值（Max/Min 成对出现，单位以系统为准）
    "tempMax/Min", "humidityMax/Min", "precipitationMax/Min",
    "uwindMax/Min", "vwindMax/Min", "waveHeightMax/Min",
    "seaTempMax/Min", "eastwardSeaWaterMax/Min", "northwardSeaWaterMax/Min",
    "cloudMax", "kssj", "jssj", "id", "hjnm", "xdnm"
  }
}
```

### 4.3 `yb[]` 兵力条目

```
{
  "dwsxnm": "<对象系统编号（如 01/02，区分蓝红双方）>",   // 可选：精简想定本级只有 data
  "data": {
    "dwsxnm": "<对象系统编号>",
    "time": "YYYY-MM-DD HH:MM:SS",     // 可选：数据保存时间
    "yjfamc": "<预警方案名称，可空>",     // 可选：预警方案【推测】
    "yjfanm": "<32位预警方案编号hash>",   // 可选【推测】
    "zyxx": 0,                          // 可选：资源信息标志（样例为 0）【推测】
    "config": {                          // 可选：链路配置（精简想定无此段）
      "connectconfig": {                // 系统间链路关系图（节点+时延）
        "chain": { "<节点类型码>": ["<下游节点类型码>", ...] },
        "connectRelation": { "<节点类型码>": <数值> },
        "delay": { "<节点类型码>": <数值 或 { "<时延分项码>": <数值> }> }
      },
      "modelconfig": [],                // 模型配置（样例为空数组）
      "ruleconfig": []                   // 规则配置（样例为空数组）
    },
    "resource": {
      "dwsxnm": "<对象系统编号>",

      "yjfamc": "…", "yjfanm": "…", "zyxx": 0   // 可选：与 data 级同名字段（填相同值）
    }
  }
}
```

## 5. 模版③：事件态势（NDJSON 事件流）

**格式**：每行一帧，帧头 5 个字段固定，事件放在 `eventList[]`（可为空）。【事实】

### 5.1 帧头

```
{
  "simulationTime": "YYYY/MM/DD HH:MM:SS",   // 当前仿真时刻
  "simulatorID": "<仿真器UUID>",
  "simulatorStatus": "1",                     // 状态码（样例恒为 1）
  "startTime": "YYYY/MM/DD HH:MM:SS",        // 仿真起始（全程不变）
  "endTime":   "YYYY/MM/DD HH:MM:SS",        // 仿真结束（全程不变）
  "eventList": [ ... ]
}
```

### 5.2 `eventList[]` 事件通用字段（任何事件都有）

| 字段 | 说明【推测】 |
|---|---|
| `cmreCode` / `cmreName` | 事件分类码（CMRE 开头）+ 分类名（如"产生实体毁伤事件"） |
| `srcID` / `entityName` | 事件来源实体 ID + 名称（可空） |
| `destID` | 事件接收/目标方（可空） |
| `side` | 归属阵营 `Blue` / `Red` |
| `timeStamp` | 事件发生时刻（相对秒字符串，如 `"30.000000"`） |
| `importance` | 重要度（样例恒为 `"0"`） |
| `message` | 人读文本描述（`"某实体 在：[t]时刻；在：{lon,lat,alt}位置 …"`） |
| `location` | JSON 字符串：`{"lon":…, "lat":…, "alt":…}` |
| `eventType` | 事件类型，样例出现：`Log` / `Report` / `Task` / `报告事件` |

### 5.3 事件扩展字段（按事件类型选填）

| 分组 | 字段 |
|---|---|
| 实例动作 | `instCode`、`instName`（实例动作码/名）、`eventRes`（`Task`/`Func`）、`exeRule` |
| 目标 | `targetID`、`targetName`、`subtargetID`、`subtargetName`、`targetLocation`(JSON串)、`targetIdList`/`targetLocationList`/`countPerTargetList`（JSON 数组串） |
| 编队 | `formationID`、`formationName`、`formationStruct`、`formationMount`（均为 JSON 字符串） |
| 命中/毁伤 | `hitterId`、`hittedCount`、`hitPercent`、`hitpercentList`、`damageValue`、`damagePercent`、`damageLevel`（如"退出仿真"）、`quitType`（如"毁伤导致退出"）、`EntDamStruct`、`SubEntDamState` |
| 武器参数 | `weaponType`、`weaponCount`、`weaponSubClass`、`weaponClass`、`missileNum`、`impactSpeed`、`desiredSpeed`、`desiredHeight`、`desiredYaw`、`chargeMass`、`chargeDiameter`、`chargeForm`、`chargeShellThickness`、`warheadQuality`、`tNTEquivalent`、`circularProbabilityError`、`penetrationDepth`、`maxBlastHeight`、`minBlastHeight`、`clusterBombThrowingRange`、`subBombCount`、`subBombType`、`subBombDamageRadius` |
| 导引/拦截 | `fuzeType`、`path`（航迹点数组 JSON 串）、`detailInterceptMessage` |
| 干扰 | `jamMode`（如"干扰类型"） |
| 报告类 | `infoErrorList`、`infoReportTimeList`、`finishTime`、`value` |

## 6. 模版④：实体态势（NDJSON 状态流）

**格式**：每行一帧，帧头 6 个字段（比事件流多 `step_cnt`），实体状态放在 `entityList[]`。采样周期 10 秒【事实：样例时间戳间隔 10s】。

### 6.1 帧头

```
{
  "simulationTime": "YYYY/MM/DD HH:MM:SS",
  "simulatorID": "<仿真器UUID>",
  "simulatorStatus": "1",
  "startTime": "…", "endTime": "…",
  "step_cnt": 1,                          // 步序号，从 1 递增
  "entityList": [ ... ]
}
```

### 6.2 `entityList[]` 单实体字段

**核心字段（所有实体都有）**【事实】：

| 字段 | 说明【推测】 |
|---|---|
| `EntityID` | 38 位长 ID（与想定/事件中的 ID 对应） |
| `EntityName` | 实例名称 |
| `EntityType` | 类型码（如"机场"、"某舰"、"某发射部队"、`AircraftFormation`(空中编队)、某导弹型） |
| `Side` | `Blue` / `Red` |
| `TimeStamp` | 绝对时间 `YYYY-MM-DD HH:MM:SS.mmm` |
| `EPLongitude` / `EPLatitude` / `EPAltitude` | 位置（经度/纬度/海拔，十进制定点 6 位字符串） |
| `EPYaw` / `EPPitch` / `EPRoll` | 航向/俯仰/横滚角 |
| `EntitySpeed` | 速度 |
| `FuelQuantity` | 剩余燃料（静态设施为 0） |
| `DamagePercent` | 毁伤百分比 |
| `FirstCfn`/`SecondCfn`/`ThirdCfn`/`ForthCfn` | 四级分类名。样例值域：一级 `设施/物资`；二级 `陆上/海上/空中`；三级 `机场/车辆/舰船/飞机/导弹`；四级 `发射车/电子战飞机` 等 |
| `WeaponMountList` | 挂载列表 JSON 字符串：`{"WeaponMountList":[{"WeaponName":"某弹","WeaponCount":n,…}]}` |
| `SubEntDamState` / `SubTarDamState` / `EPFormation` | 子实体/子目标毁伤状态、所属编队（可为空串） |

**可选字段（按实体类型出现）**：

| 分组 | 字段 | 出现于【推测】 |
|---|---|---|
| 任务 | `ETaskName`（当前任务名，如"空中编队盘旋"）、`ETaskState`（`running`/`success`…） | 空中平台 |
| 电子工作 | `EISwitch`、`EIRange`、`EIHAngle`、`EIStartHAngle`（均 `{"default":…}` 格式） | 电子对抗平台 |
| 行为状态 | `ECActionState`（`{"ActCount":n,"ActStateList":[…]}` JSON 串） | 机动平台 |
| 传感器 | `DetectRange`、`DetectTarList`、`SensorFOVH` | 带探测传感器实体 |
| 开关状态 | `SWorkState`（`{"default":0}`） | 武器/功能单元 |

## 8. 使用模版生成新文件的步骤（建议）

1. **想定**：复制样例 → 改 `cjlx`/`startTime`/`endTime`/`ybnm`；环境树按实际区域改 `hjmc`/`qydw` 边界点；双方 `yb` 各一条，`trooplist` 按部署逐条填写（经纬高 + 装备构成）。
2. **指令**：每条规则一条 `rules[]`；`action` 写"执行者→目标→武器/区域/航路 + 起止秒"；`ruleconfig` 只按需开策略开关。
3. **实体态势**：固定帧头 + 逐帧更新 `entityList`；实体集合与想定兵力一致，ID 对齐。
4. **事件态势**：固定帧头；事件按需写入 `eventList`，通用字段必填、扩展字段按事件类型补。
5. 一致性校验：四者共用同一套实体 ID、`simulatorID`、仿真起止时间；所有数值字段保持"6 位小数字符串"约定。

## 9. 脱敏说明

本总结中以下样例内容已被泛化，正式使用时以内部数据回填：
- 装备型号/名称 → `某机型`、`某导弹`、`<模型类型码>`；
- 具体地名 → `某区域`、`某海域`；
- 具体实例 ID、UUID、类型码实例值 → `<编号>` / `<类型码>` 占位符；
- 保留的字段名、字段含义说明、数值格式约定均来自样例文件的公开结构，不涉及具体部署信息。
